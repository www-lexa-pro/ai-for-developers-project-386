# Render: подключение и деплой

Конфигурация первого учебного сервиса — в render.yaml: Docker, Free,
Frankfurt, main, проверка /api/health. Обновления выполняются вручную,
по команде Алексея; автоматический деплой выключен. БД, диски и платные
ресурсы не создаются. Если Render требует карту или оплату — остановиться.

## Подключение Codex MCP

Регистрация и вход в Dashboard сами по себе не дают MCP доступа.
Официальный сервер поддерживает отдельное разрешение OAuth:

```bash
codex mcp add render --url https://mcp.render.com/mcp --oauth-client-id codex
codex mcp get render
```

Разрешить доступ в браузере к своему аккаунту Render. Отдельный API-ключ
при OAuth не нужен. Разрешение предоставляет права аккаунта на доступные
рабочие пространства; использовать только рабочее пространство Алексея.
Учётные данные сохраняет Codex вне репозитория. Не копировать сюда ключи,
OAuth-токены, одноразовые коды, callback URL или персональные auth-файлы.

Если сервер уже добавлен, повторный вход: `codex mcp login render`.
Если браузер на Windows, а Codex на NAS, callback на 127.0.0.1 относится
к машине Codex: нужен туннель или безопасная передача одноразового ответа
локальному процессу Codex без записи в Git и журналы.

После подключения открыть новый диалог Codex, если инструменты MCP не
появились в текущем. Проверить list_workspaces, выбрать своё workspace,
затем list_services. Успешный OAuth сам по себе не доказывает успешный
вызов инструментов. Отключение: `codex mcp logout render`, удаление
настройки: `codex mcp remove render`.

Для неинтерактивного подключения альтернативой служит API-ключ:
`codex mcp add render --url https://mcp.render.com/mcp --bearer-token-env-var RENDER_API_KEY`.
Сам ключ передавать только через окружение вне Git; не добавлять его
в render.yaml или приложение.

## Первый запуск

Render должен получить опубликованный Git-коммит с Dockerfile.
Создать один Web Service из публичного URL репозитория, выбрать Docker,
main, Frankfurt, Free, Dockerfile в корне и health check /api/health.
Не переопределять команду запуска: ENTRYPOINT запускает Go автоматически.
PORT предоставляет Render, STATIC_DIR уже задан в образе.
Если используется Blueprint, применить render.yaml с теми же настройками.

Проверить успешный статус деплоя, / и /api/health, прямые ссылки /owner
и /meeting-types/<id>, затем создать тестовый тип и бронирование и
проверить его у владельца. В тестах использовать только вымышленные данные.

## Ограничения учебного приложения

Вместо БД используется память одного Go-процесса. Перезапуск, новый деплой
и пробуждение после сна сбрасывают типы и бронирования. Free засыпает
после 15 минут без входящего трафика, пробуждение может занять около минуты.
Авторизации нет: страница владельца и данные гостей доступны публично.

Проверено по документации 17.11.2026:
- https://render.com/docs/mcp-server
- https://render.com/docs/free
- https://render.com/docs/blueprint-spec
- https://ru.hexlet.io/blog/posts/kak-deploit-prilozhenie-na-render-gayd-dlya-frontenderov-i-bekenderov
